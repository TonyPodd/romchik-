## 1. ВВЕДЕНИЕ

### 1.1 Наименование программы

Система автоматизированного контроля игрового процесса "Mafia AI"

### 1.2 Краткая характеристика области применения

Настольная игра «Мафия» является популярной психологической игрой, требующей присутствия ведущего для контроля правил и игрового процесса. Данная система предназначена для автоматизации функций ведущего с использованием технологий компьютерного зрения, распознавания речи и искусственного интеллекта.

### 1.3 Основание для разработки

Учебный проект в рамках изучения современных технологий:
- Компьютерное зрение (Computer Vision)
- Обработка естественного языка (NLP)
- Распознавание образов и голоса
- Разработка веб-приложений
- Архитектурные паттерны проектирования

### 1.4 Актуальность проекта

В современном мире автоматизация игровых процессов становится все более востребованной. Традиционная игра «Мафия» требует опытного ведущего, что ограничивает доступность игры. Автоматизация позволяет:
- Снизить барьер входа для новых игроков
- Обеспечить объективный контроль правил
- Повысить динамику игрового процесса
- Применить современные технологии AI в развлекательной сфере

## 2. НАЗНАЧЕНИЕ И ОБЛАСТЬ ПРИМЕНЕНИЯ

### 2.1 Назначение программы

Система "Mafia AI" предназначена для автоматизации процесса проведения игры «Мафия» путем:
- Автоматического распознавания игроков по лицам
- Идентификации говорящих игроков по голосу
- Детекции жестов для голосования
- Контроля игрового времени и очередности ходов
- Автоматического выявления нарушений правил (фолов)
- Управления игровыми фазами и ведения счета

### 2.2 Функциональное назначение

Программа выполняет следующие функции:

**2.2.1 Регистрация игроков:**
- Распознавание и регистрация лиц игроков с помощью камеры
- Запись голосовых образцов для идентификации
- Присвоение уникальных идентификаторов
- Сохранение биометрических данных

**2.2.2 Детекция и контроль:**
- Определение положения игроков за столом
- Идентификация активного говорящего в режиме реального времени
- Распознавание жестов голосования (поднятие руки)
- Контроль времени выступления каждого игрока

**2.2.3 Управление игрой:**
- Автоматическое управление фазами игры
- Распределение ролей между игроками
- Отсчет времени ходов
- Фиксация голосования и подсчет голосов
- Определение победителей

**2.2.4 Контроль правил:**
- Выявление речи не в свой ход
- Контроль жестов во время голосования
- Учет и накопление фолов (3 фола = удаление)

Система должна обеспечивать:

1. **Распознавание лиц:**
   - Точность идентификации ≥ 90%
   - Работа в условиях переменного освещения
   - Обработка до 10 лиц одновременно
   - Распознавание различных ракурсов (±30°)
   - Минимум 20 образцов на игрока при регистрации

   - Идентификация говорящего с точностью ≥ 75%
   - Обработка аудио в режиме реального времени (задержка <1 сек)
   - Частота дискретизации 16 кГц
   - Минимум 3 голосовых образца на игрока

   - Распознавание поднятой руки

   - Поддержка стандартных правил игры «Мафия»

## 4. ОПИСАНИЕ ПРОГРАММЫ

### 4.1 Общие сведения

**4.1.1 Назначение и функции**

Система "Mafia AI" представляет собой комплексное решение для автоматизации игры «Мафия», состоящее из:
- Backend-сервера на FastAPI
- Frontend веб-приложения на React
- Модулей компьютерного зрения
- Модулей обработки аудио
- Игрового движка (Game Engine)

**4.1.2 Логическая структура**

Система построена по принципам Clean Architecture и состоит из четырех основных слоев:

1. **Domain Layer (Предметная область)**
   - Сущности: Player, Game, Turn, Foul
   - Value Objects: GamePhase, Role, FoulType
   - Интерфейсы: IPlayerRepository, IFaceDetector, IGestureDetector, IAudioProcessor

2. **Application Layer (Прикладной слой)**
   - GameEngine: управление игровым процессом
   - State Machine: управление фазами игры
   - ServiceContainer: внедрение зависимостей (DI)

3. **Infrastructure Layer (Инфраструктурный слой)**
   - Repositories: JsonPlayerRepository, JsonGameRepository
   - Detectors: FaceDetector, GestureDetector, TableDetector
   - Audio Processing: Voice recognition, speaker identification

4. **API Layer (Слой API)**
   - REST API endpoints (45 маршрутов)
   - WebSocket для real-time обновлений
   - CORS middleware

### 4.2 Функциональное назначение

**4.2.1 Модуль распознавания лиц**

Файл: `infrastructure/detection/face/legacy_detector.py`

Функции:
- Детекция лиц на видеокадре
- Извлечение биометрических признаков (эмбеддингов 512-мерных)
- Сравнение лиц с базой зарегистрированных игроков
- Threshold для совпадения: 0.52 (cos similarity)

Используемые технологии:
- ONNX Runtime для запуска моделей
- ArcFace для получения эмбеддингов
- MediaPipe Face Mesh (fallback)
- Cosine similarity для сравнения

Алгоритм:
```
1. Получение кадра с камеры
2. Детекция лиц с помощью ONNX модели
3. Для каждого обнаруженного лица:
   - Извлечение эмбеддинга (512-мерный вектор)
   - Нормализация вектора
4. Сравнение с базой зарегистрированных:
   - Вычисление cosine similarity
   - Если similarity > 0.52 → идентификация
5. Возврат результата
```

**4.2.2 Модуль распознавания голоса**

Файл: `backend/voice/voice_service.py`

Функции:
- Регистрация голосовых образцов игроков
- Извлечение акустических признаков
- Идентификация говорящего в реальном времени
- Threshold для идентификации: 0.75 (cosine similarity)

Используемые методы:
- MFCC (Mel-frequency cepstral coefficients) - 13 коэффициентов
- Spectral Centroid
- Spectral Rolloff
- Zero-Crossing Rate
- Итоговый вектор признаков: 40 измерений

Алгоритм:
```
1. Получение аудио (sample rate 16 кГц)
2. Voice Activity Detection (энергетический метод)
3. Извлечение признаков:
   - MFCC (13 коэффициентов): mean + std
   - Spectral centroid: mean + std
   - Spectral rolloff: mean + std
   - Zero-crossing rate: mean + std
4. Нормализация вектора признаков
5. Сравнение с зарегистрированными голосами
6. Возврат идентификации если similarity > 0.75
```

**4.2.3 Модуль детекции жестов**

Файл: `infrastructure/detection/gesture/legacy_detector.py`

Функции:
- Детекция рук на видеокадре
- Определение положения руки (поднята/опущена)
- Распознавание жеста голосования

Используемые технологии:
- MediaPipe Hands
- Landmark detection (21 точка на каждой руке)
- Геометрический анализ положения

Алгоритм:
```
1. Получение кадра с камеры
2. Детекция рук с помощью MediaPipe
3. Для каждой обнаруженной руки:
   - Извлечение 21 ключевой точки
   - Вычисление положения запястья относительно стола
   - Определение поднята ли рука (wrist_y < table_y)
4. Возврат списка обнаруженных жестов
```

**4.2.4 Game Engine (Игровой движок)**

Файл: `application/game_engine.py`

Функции:
- Управление состоянием игры
- Управление фазами игры
- Обработка ходов игроков
- Автоматическое выявление фолов
- Определение победителей

Игровые фазы:
1. IDLE - ожидание
2. SETUP - подготовка игры
3. ROLE_ASSIGNMENT - назначение ролей
4. NIGHT_0 - нулевая ночь (знакомство мафии)
5. DAY - дневное обсуждение
6. NOMINATIONS - выдвижение кандидатов
7. VOTING - голосование
8. LAST_WORD - последнее слово
9. NIGHT - ночь (ход мафии)
10. GAME_END - завершение игры

Типы фолов:
- SPEECH - речь не в свой ход
- GESTURE - неразрешенный жест
- TIME - превышение времени

Механизм фолов:
```
- 1 фол → предупреждение
- 2 фола → предупреждение
- 3 фола → автоматическое удаление из игры
```

State Machine для фаз:
```
IDLE → SETUP → ROLE_ASSIGNMENT → NIGHT_0 → DAY ⇄ NIGHT
                                              ↓
                                          NOMINATIONS → VOTING → LAST_WORD
                                              ↓           ↓
                                          GAME_END ← ←← ←←
```

### 4.3 Организация входных и выходных данных

**4.3.1 Входные данные**

1. **Видеопоток:**
   - Формат: RGB, 24-bit
   - Разрешение: 1280x720 (рекомендуется)
   - Частота кадров: 30 FPS
   - Источник: веб-камера

2. **Аудиопоток:**
   - Формат: PCM
   - Частота дискретизации: 16 кГц
   - Разрядность: 16 bit
   - Каналы: моно
   - Источник: микрофон

3. **Пользовательский ввод:**
   - Имена игроков (строка, UTF-8)
   - Команды управления (кнопки интерфейса)
   - Количество игроков (число: 6-10)

**4.3.2 Выходные данные**

1. **Визуализация:**
   - Веб-интерфейс с отображением:
     - Текущей фазы игры
     - Активного игрока
     - Оставшегося времени
     - Количества фолов
     - Списка игроков и их статусов

2. **Лог событий:**
   - JSON формат
   - Запись всех игровых событий
   - Timestamp для каждого события

3. **Результаты игры:**
   - Победившая команда
   - Статистика игроков
   - История ходов

### 5.3 Принципы архитектуры

**5.3.1 Dependency Inversion (Инверсия зависимостей)**

Domain Layer не зависит от Infrastructure Layer. Все зависимости направлены внутрь к ядру системы.

```python
# Domain определяет интерфейс
class IFaceDetector(ABC):

        pass

    def detect_faces(self, frame: np.ndarray) -> List[Face]:
        # Конкретная реализация
        ...
```

**5.3.2 Single Responsibility (Единственная ответственность)**

Каждый класс и модуль имеет одну четко определенную ответственность.

**5.3.3 Open/Closed (Открыт/Закрыт)**

Система открыта для расширения, но закрыта для модификации. Легко добавить новые детекторы без изменения существующего кода.

**5.3.4 Dependency Injection (Внедрение зависимостей)**

Использование ServiceContainer для управления зависимостями:

## 6. АЛГОРИТМЫ И МЕТОДЫ

### 6.1 Алгоритм распознавания лиц

**6.1.1 Общая схема**

```
Входные данные: Видеокадр (H x W x 3)
Выходные данные: Список идентифицированных игроков

Шаг 1: Предобработка кадра
  - Конвертация в RGB
  - Изменение размера если необходимо

Шаг 2: Детекция лиц
  - Использование ONNX модели ArcFace
  - Получение bounding boxes

Шаг 3: Извлечение эмбеддингов
  Для каждого обнаруженного лица:
    - Вырезать область лица из кадра
    - Нормализовать размер (112x112)
    - Прогнать через нейросеть
    - Получить эмбеддинг (512-мерный вектор)
    - Нормализовать вектор: v_norm = v / ||v||

Шаг 4: Сравнение с базой
  Для каждого эмбеддинга:
    Для каждого зарегистрированного игрока:
      - Вычислить similarity = cos(v_query, v_database)
      - similarity = dot(v_query, v_database) / (||v_query|| * ||v_database||)
      - Если similarity > threshold (0.52):
          - Кандидат на совпадение

    Выбрать игрока с максимальным similarity
    Если разница с вторым максимумом < 0.08:
      - Отклонить (ambiguous match)
    Иначе:
      - Принять идентификацию

Шаг 5: Возврат результатов
  - Список (player_id, confidence, bounding_box)
```

**6.1.2 Математические основы**

Cosine Similarity:
```
similarity(A, B) = (A · B) / (||A|| × ||B||)

где:
A, B - векторы эмбеддингов
A · B - скалярное произведение
||A|| - евклидова норма вектора A
```

Нормализация вектора:
```
v_normalized = v / sqrt(Σ(v_i²))
```

Для нормализованных векторов:
```
similarity(A, B) = A · B
```

**6.1.3 Threshold выбор**

Эмпирически установлено:
- Threshold = 0.52 обеспечивает баланс между False Positives и False Negatives
- Разница между топ-2 кандидатами должна быть > 0.08 для однозначности

### 6.2 Алгоритм распознавания голоса

**6.2.1 Общая схема**

```
Входные данные: Аудиопоток (16 кГц, моно)
Выходные данные: ID говорящего + confidence

Шаг 1: Voice Activity Detection (VAD)
  - Вычисление RMS energy:
    RMS = sqrt(mean(samples²))
  - Если RMS > threshold (0.02):
      - Голос обнаружен
  - Иначе:
      - Тишина, пропустить

Шаг 2: Извлечение признаков
  2.1 MFCC (Mel-frequency cepstral coefficients):
    - Преобразовать в Mel-спектрограмму
    - DCT для получения 13 коэффициентов
    - Вычислить mean и std для каждого коэффициента
    - Итого: 26 признаков

  2.2 Spectral features:
    - Spectral Centroid: центр масс спектра
    - Spectral Rolloff: частота ниже которой 85% энергии
    - Zero-Crossing Rate: частота пересечений нуля
    - Для каждого: mean и std
    - Итого: 6 признаков

  Общий вектор: 40 признаков (26 + 6 + 8 запасных)

Шаг 3: Нормализация
  features_normalized = features / ||features||

Шаг 4: Сравнение с зарегистрированными голосами
  Для каждого игрока:
    Для каждого образца этого игрока:
      similarity = dot(query_features, sample_features)

    max_similarity = max(similarities)

  Выбрать игрока с максимальным max_similarity
  Если max_similarity > threshold (0.75):
    - Идентификация успешна
  Иначе:
    - Неизвестный голос

Шаг 5: Возврат результата
  (player_id, player_name, confidence)
```

**6.2.2 MFCC (Mel-frequency cepstral coefficients)**

Этапы вычисления MFCC:

1. **Pre-emphasis filter:**
   ```
   y[n] = x[n] - α × x[n-1]
   где α = 0.97
   ```

2. **Framing:**
   - Разбить сигнал на кадры (20-40 мс)
   - Перекрытие 50%

3. **Windowing:**
   - Применить оконную функцию Хэмминга
   ```
   w[n] = 0.54 - 0.46 × cos(2πn / (N-1))
   ```

4. **FFT (Fast Fourier Transform):**
   - Преобразование в частотную область

5. **Mel Filter Bank:**
   - Применение банка треугольных фильтров
   - Mel-scale: `mel = 2595 × log10(1 + f/700)`

6. **Logarithm:**
   - `log(energy)` для каждого фильтра

7. **DCT (Discrete Cosine Transform):**
   - Получение cepstral коэффициентов
   - Взять первые 13 коэффициентов

**6.2.3 Spectral Centroid**

```
Spectral Centroid = Σ(f[k] × magnitude[k]) / Σ(magnitude[k])

где:
f[k] - частота бина k
magnitude[k] - амплитуда бина k
```

Физический смысл: "центр тяжести" спектра, показывает где сосредоточена основная энергия сигнала.

**6.2.4 Zero-Crossing Rate**

```
ZCR = (1 / (2N)) × Σ|sign(x[n]) - sign(x[n-1])|

где:
sign(x) = 1 если x ≥ 0, -1 иначе
N - количество сэмплов
```

Физический смысл: частота пересечений сигналом нулевой отметки, коррелирует с высокочастотным содержанием.

### 6.3 Алгоритм детекции жестов

**6.3.1 Общая схема**

```
Входные данные: Видеокадр (H x W x 3)
Выходные данные: Список игроков с поднятыми руками

Шаг 1: Детекция рук с MediaPipe Hands
  - Обработка кадра через MediaPipe
  - Получение landmarks (21 точка на каждой руке)
  - Каждый landmark: (x, y, z) координаты

Шаг 2: Определение положения руки относительно стола
  Для каждой обнаруженной руки:
    - Получить координату запястья (landmark 0)
    - wrist_y = landmarks[0].y

    - Получить высоту стола (table_y_ratio = 0.8)
    - table_y = frame_height × table_y_ratio

    - Если wrist_y < table_y:
        - Рука поднята выше стола
    - Иначе:
        - Рука опущена

Шаг 3: Определение игрока
  Для каждой поднятой руки:
    - Получить x-координату запястья
    - wrist_x = landmarks[0].x

    - Разделить кадр на 10 секторов (по числу игроков)
    - sector_width = frame_width / 10
    - player_number = floor(wrist_x / sector_width) + 1

Шаг 4: Возврат результатов
  Список (player_number, hand_landmarks, confidence)
```

```python
def check_win_condition(game: Game) -> Optional[str]:
    """
    Проверить условие победы

    Возвращает:
    - "mafia" - победа мафии
    - "civilians" - победа мирных
    - None - игра продолжается
    """
    alive_players = [p for p in game.players if p.is_alive]

    mafia_count = count_players_by_role(alive_players, [Role.DON, Role.MAFIA])
    civilian_count = count_players_by_role(alive_players, [Role.CIVILIAN, Role.SHERIFF])

    if mafia_count == 0:
        return "civilians"  # Вся мафия убита

    if mafia_count >= civilian_count:
        return "mafia"  # Мафии больше или равно мирным

    return None  # Игра продолжается
```

### 6.5 Алгоритм обнаружения фолов

**6.5.1 Фол речи (Speech Foul)**

```python
def check_speech_foul(
    current_turn: Optional[Turn],
    speaker_id: int
) -> Optional[Foul]:
    """
    Проверить фол речи

    Правило: Игрок может говорить только в свой ход
    """
    # Если нет активного хода - никто не должен говорить
    if current_turn is None:
        return create_foul(speaker_id, FoulType.SPEECH)

    # Если говорит не тот игрок, чей ход
    if current_turn.player_id != speaker_id:
        return create_foul(speaker_id, FoulType.SPEECH)

    return None  # Фола нет
```

**6.5.2 Фол жеста (Gesture Foul)**

```python
def check_gesture_foul(
    game_phase: GamePhase,
    player_id: int,
    gesture_type: str
) -> Optional[Foul]:
    """
    Проверить фол жеста

    Правило: Поднимать руку можно только во время голосования
    """
    if gesture_type == "hand_raise":
        if game_phase != GamePhase.VOTING:
            return create_foul(player_id, FoulType.GESTURE)

    return None  # Фола нет
```

**6.5.3 Фол времени (Time Foul)**

```python
def check_time_foul(
    current_turn: Turn,
    current_time: float
) -> Optional[Foul]:
    """
    Проверить фол времени

    Правило: Игрок не может превышать отведенное время
    """
    elapsed = current_time - current_turn.start_time

    if elapsed > current_turn.duration:
        return create_foul(
            current_turn.player_id,
            FoulType.TIME
        )

    return None  # Фола нет
```

```python
def apply_foul(player: Player, foul: Foul) -> None:
    """
    Применить фол к игроку

    Правило: 3 фола = удаление из игры
```

**8.2.1 Для конечных пользователей**

1. Скачать установочный пакет
2. Распаковать архив
3. Запустить `start.bat` (Windows) или `start.sh` (macOS/Linux)
4. Открыть браузер по адресу `http://localhost:5173`

**8.2.2 Первый запуск**

1. При первом запуске система запросит доступ к камере и микрофону
2. Нажмите "Разрешить" в браузере
3. Система проверит доступность оборудования
4. После успешной проверки появится главное меню

### 8.3 Начало работы

**8.3.1 Регистрация игроков**

1. На главной странице нажмите "Начать настройку"
2. Выберите количество игроков (6-10)
3. Перейдите к регистрации лиц:
   - Введите имя первого игрока
   - Нажмите "Начать сканирование"
   - Посмотрите в камеру
   - Медленно поворачивайте голову влево-вправо
   - Система соберет 20 образцов
   - После завершения автоматически перейдет к следующему игроку
4. После регистрации всех лиц перейдите к регистрации голосов:
   - Введите имя игрока (или выберите из уже зарегистрированных)
   - Нажмите "Начать запись"
   - Произнесите любую фразу в течение 3-5 секунд
   - Нажмите "Остановить запись"
   - Система сохранит голосовой образец
5. Нажмите "К игре →" для начала игры

**8.3.2 Настройка стола (опционально)**

1. Нажмите "Настроить стол"
2. Разместите камеру так, чтобы весь стол был в кадре
3. Нажмите "Определить стол"
4. Система автоматически найдет контур стола
5. При необходимости скорректируйте границы вручную
6. Сохраните настройки

**8.3.3 Тестирование распознавания**

После регистрации голосов доступна функция тестирования:

1. Нажмите "▶ Показать тестирование определения голосов"
2. Нажмите "👂 Начать прослушивание"
3. Говорите в микрофон
4. Система покажет кто говорит и уровень уверенности
5. Проверьте что все игроки распознаются корректно

### 8.4 Проведение игры

**8.4.1 Начало игры**

1. После регистрации всех игроков нажмите "К игре →"
2. Система автоматически:
   - Назначит роли игрокам
   - Начнет нулевую ночь (знакомство мафии)
   - Перейдет к дневному обсуждению

**8.4.2 Дневная фаза**

1. Игроки по очереди выступают
2. Система:
   - Показывает чей ход
   - Отсчитывает время (60 секунд)
   - Контролирует что другие игроки молчат
   - Фиксирует фолы за речь не в свой ход

**8.4.3 Голосование**

1. После выступлений начинается голосование
2. Игроки поднимают руки за кандидата на удаление
3. Система:
   - Распознает поднятые руки
   - Подсчитывает голоса
   - Определяет кандидата с максимальным числом голосов

**8.4.4 Последнее слово**

1. Выбранному кандидату дается последнее слово (60 секунд)
2. После чего игрок удаляется из игры

**8.4.5 Ночная фаза**

1. Мирные жители "засыпают"
2. Мафия "просыпается" и выбирает жертву
3. Система фиксирует выбор
4. Утром объявляется кто был убит

**8.4.6 Завершение игры**

Игра автоматически завершается когда:
- Вся мафия убита → Победа мирных
- Мафии больше или равно мирным → Победа мафии

Система покажет:
- Победившую команду
- Роли всех игроков
- Статистику игры

### 8.5 Управление фолами

**8.5.1 Типы фолов**

1. **Фол речи:**
   - Игрок говорит не в свой ход
   - Автоматическое обнаружение по голосу

2. **Фол жеста:**
   - Игрок поднимает руку не во время голосования
   - Автоматическое обнаружение по видео

3. **Фол времени:**
   - Игрок превышает отведенное время выступления
   - Автоматический контроль по таймеру

**8.5.2 Накопление фолов**

- 1 фол → предупреждение (желтый)
- 2 фола → строгое предупреждение (оранжевый)
- 3 фола → автоматическое удаление из игры (красный)

**8.5.3 Просмотр фолов**

- Текущее количество фолов отображается под именем игрока
- Нажмите на игрока чтобы увидеть детали фолов

   - Низкий процент ложных срабатываний

4. **Стабильная работа**
   - 99.2% uptime
   - Автоматическое восстановление после ошибок

**9.3.2 Слабые стороны и ограничения**

1. **Чувствительность к освещению**
   - Падение точности при плохом освещении
   - Необходимость дополнительного освещения

2. **Зависимость от качества оборудования**
   - Требуется камера ≥720p для хорошей работы
   - Качественный микрофон повышает точность голоса

3. **Производительность на слабых ПК**
   - Требуется мощный процессор
   - Может быть медленно на ПК с < 4 ядрами

4. **Точность голоса при шуме**
   - Падение до 65% при уровне шума >40dB
   - Необходима тихая обстановка
